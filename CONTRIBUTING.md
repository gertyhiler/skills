# Contributing

Start with a real task or a demonstrated failure of the current instructions.
Describe the expected outcome, the relevant project contract and what the agent
actually did. Keep examples free of private paths, credentials and client data.

Keep each skill independently useful. Avoid adding an obligatory second skill,
review loop, service or company-wide policy to fix one local case. Put long,
conditional procedures in linked references only when needed.

Run make check. For changes to Git, cleanup or delivery behavior, inspect realistic
success and failure scenarios in a disposable repository; never test destructive
instructions against a working project. Report checks and remaining uncertainty.
Markdown validation is not behavioral validation.
